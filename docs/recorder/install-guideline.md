## 1. 문서 개요

### 1-1. 목적

이 문서는 Vital Recorder 장비를 신규 이미지로 초기화하고, 병원 네트워크 및 Vital Server에 연결하기 위한 설치 가이드라인입니다.

주요 범위는 다음과 같습니다.

* Vital Recorder 장비 초기화
* PiVR 이미지 설치
* 최초 부팅 및 관리자 페이지 접속
* 네트워크 설정
* Vital Server 연결
* 의료기기 Device 설정
* 설치 후 정상 동작 확인
* 기본 문제 진단

### 1-2. 적용 대상

본 가이드는 다음 장비를 대상으로 합니다.

* VRS
* VRZero 2W
* VRZ 2W

다음 장비에는 적용하지 않습니다.

* VRZ W 1세대

VRZ W 1세대는 신규 64bit 이미지와 호환되지 않을 수 있으므로 별도 32bit 이미지 사용 여부를 확인해야 합니다.

### 1-3. 기본 원칙

기존 장비에서 업그레이드가 정상 반영되지 않거나 부팅 문제가 발생하는 경우, 기존 방식의 업데이트보다 **SD 카드에 신규 이미지를 다시 설치하는 방식**을 권장합니다.

특히 기존 Vital Recorder 버전이 오래된 경우에는 자동 업그레이드가 실패하거나, 업그레이드 후에도 버전이 유지되는 문제가 발생할 수 있습니다.

## 2. 설치 전 확인 사항

### 2-1. 장비 모델 확인

설치 전 장비 모델을 먼저 확인합니다.

신규 PiVR 이미지는 다음 모델에서 사용 가능합니다.

* VRS
* VRZero 2W
* VRZ 2W

구형 VRZ 장비는 하드웨어 사양에 따라 64bit 이미지가 정상 동작하지 않을 수 있습니다. 이 경우 32bit 이미지가 필요합니다.

### 2-2. 현재 버전 확인

기존 장비의 Vital Recorder 버전을 확인합니다.

예를 들어 PDF에서는 기존 장비에 다음 버전이 확인되었습니다.

* 1.9.8
* 1.9.2

기존 버전도 사용은 가능하지만, 네트워크 문제나 서버 연결 오류 상황에서 Vital Recorder가 재시작되거나 파일 저장이 비정상 종료될 수 있습니다. 따라서 문제가 반복되는 장비는 신규 이미지로 재설치하는 것이 더 안전합니다.

### 2-3. 서버 정보 확인

설치 전에 Vital Server 정보를 확보합니다.

필수 확인 항목은 다음과 같습니다.

* Vital Server IP
* Vital Server Port
* 병원 코드
* 서버 고정 IP 여부
* Web Monitoring 접속 가능 여부
* 파일 업로드 경로 정상 여부

보라매병원의 경우 PDF에서는 서버 설정의 `hospcode` 값을 `brmh`로 사용한다고 안내되어 있습니다.

## 3. 준비물

### 3-1. 장비 및 부품

설치에 필요한 준비물은 다음과 같습니다.

* VRS 또는 VRZero 2W
* microSD 카드
* microSD 카드 리더기
* 노트북
* LAN 케이블 1개
* 병원 WiFi 정보
* Vital Server 접속 정보

### 3-2. microSD 카드 기준

microSD 카드는 다음 기준을 권장합니다.

* 16GB 이상
* 신규 카드 권장
* 기존 데이터를 모두 삭제해도 되는 카드

이미지 설치 과정에서 microSD 카드의 기존 데이터는 모두 삭제됩니다.

### 3-3. 이미지 파일

PDF에서 사용된 이미지 파일은 다음과 같습니다.

```text
pivr-20260430.img.xz
```

해당 이미지는 PiVR `1.18.32` 버전입니다.

설치 전 `.xz` 압축을 먼저 해제하고, 압축 해제 후 생성되는 `.img` 파일을 사용합니다.

## 4. SD 카드 초기화 및 이미지 설치

### 4-1. Raspberry Pi Imager 설치

노트북에 Raspberry Pi Imager를 설치합니다.

Windows 또는 macOS 버전을 설치하면 됩니다.

### 4-2. microSD 카드 삽입

microSD 카드를 카드 리더기에 삽입한 뒤 노트북에 연결합니다.

이 단계에서 반드시 microSD 카드가 정상 인식되는지 확인합니다.

### 4-3. 이미지 쓰기 설정

Raspberry Pi Imager를 실행한 뒤 아래와 같이 설정합니다.

```text
Device: NO FILTERING
OS: Use custom
Storage: microSD 카드
```

`OS` 항목에서는 압축 해제한 `.img` 파일을 선택합니다.

주의할 점은 `Storage` 선택 단계입니다. 노트북 내부 디스크를 선택하면 데이터가 삭제될 수 있으므로 반드시 microSD 카드를 선택해야 합니다.

### 4-4. 이미지 쓰기 실행

설정이 끝나면 `WRITE`를 실행합니다.

진행 중 다음 질문이 나오면 아래처럼 선택합니다.

```text
Use OS customisation? -> NO
Continue? -> YES
```

이미지 쓰기는 보통 5~10분 정도 소요됩니다.

완료 후 microSD 카드를 안전하게 제거한 뒤 VRS 또는 VRZ 장비에 삽입합니다.

## 5. 첫 부팅 및 관리자 페이지 접속

### 5-1. 첫 부팅

microSD 카드를 장비에 삽입한 뒤 전원을 연결합니다.

USB LAN을 사용하는 경우에는 USB LAN을 먼저 연결한 뒤 전원을 연결합니다.

전원 연결 후 약 3~5분 정도 대기합니다. 이 과정에서 초기 설정과 자동 재부팅이 진행될 수 있습니다.

### 5-2. 노트북과 장비 직접 연결

Pi와 노트북을 LAN 케이블로 직접 연결합니다.

이후 노트북의 이더넷 IP를 수동으로 설정합니다.

```text
IP: 192.168.137.10
Subnet Mask: 255.255.255.0
Gateway: 비워둠
DNS: 비워둠
```

작업 완료 후에는 노트북 이더넷 설정을 다시 자동 DHCP로 되돌려야 합니다. 그렇지 않으면 일반 WiFi나 이더넷 연결이 되지 않을 수 있습니다.

### 5-3. 관리자 페이지 접속

브라우저에서 아래 주소로 접속합니다.

```text
http://192.168.137.2
```

주의할 점은 `https`가 아니라 `http`를 사용해야 한다는 점입니다.

초기 비밀번호는 다음과 같습니다.

```text
0000
```

관리자 페이지가 열리지 않으면 다음을 확인합니다.

* LAN 케이블 연결 상태
* 노트북 이더넷 IP 설정
* 노트북 WiFi 임시 비활성화
* 장비 첫 부팅 완료 여부
* 5분 추가 대기 후 재시도

## 6. 네트워크 설정

### 6-1. WiFi 설정

관리자 페이지의 `Network` 메뉴에서 병원 WiFi 정보를 입력합니다.

```text
SSID: 병원 WiFi 이름
PW: 병원 WiFi 비밀번호
User: 필요 시 입력
```

병원 WiFi가 계정 기반 인증을 사용하는 경우 `User` 값을 입력합니다.

### 6-2. Static IP 설정

고정 IP 또는 DNS가 필요한 경우에만 `Static IP Settings` 섹션을 입력합니다.

일반적으로 DHCP 환경이면 Static IP는 비워둡니다.

입력해야 하는 경우에는 병원 네트워크 담당자에게 아래 정보를 먼저 확인합니다.

* IP Address
* Subnet Mask
* Gateway
* DNS
* 병원 네트워크 접근 정책

### 6-3. Hotspot 설정

Hotspot은 필요한 경우에만 `ON`으로 설정합니다.

일반적인 병원 설치에서는 병원 WiFi 또는 유선 네트워크 연결이 우선입니다.

설정 후 반드시 `Save`를 클릭합니다.

## 7. Vital Server 및 Device 설정

### 7-1. Generals 설정

관리자 페이지의 `Generals` 탭에서 Vital Recorder 기본 정보를 설정합니다.

```text
VR Name: 침상명 또는 장비명
Vitalserver IP: 서버 주소
```

예시는 다음과 같습니다.

```text
VR Name: SICU_8
Vitalserver IP: 192.168.xxx.xxx:80
```

`VR Name`은 Web Monitoring에서 장비를 식별하는 이름이므로, 병원 내 침상명 또는 OR 이름과 일관되게 맞추는 것이 좋습니다.

### 7-2. Device 추가

의료기기는 `Devices` 탭에서 추가합니다.

절차는 다음과 같습니다.

1. `Devices` 탭으로 이동
2. `Add Device` 클릭
3. 장비 종류 선택
4. Port 설정
5. Save 클릭

기존 설정이 `F1~F4`였다면 신규 설정에서는 `P1~P4`로 맞춥니다.

예시는 다음과 같습니다.

```text
기존 F1 -> P1
기존 F2 -> P2
기존 F3 -> P3
기존 F4 -> P4
```

저장 후 Vital Recorder 프로그램은 자동으로 재시작됩니다.

### 7-3. Demo Device 설정

실제 의료기기 연결 전 테스트 목적으로 Demo Device를 추가할 수 있습니다.

예시 설정은 다음과 같습니다.

```text
[DEV/Demo]
type=Demo
```

다만 PDF에서는 Demo Device를 추가했음에도 Web Monitoring에 파형이 표시되지 않는 사례가 있었습니다. 따라서 Demo Device 결과만으로 최종 정상 여부를 판단하지 말고, 실제 의료기기 연결 후 신호 수신을 확인해야 합니다.

## 8. 설치 후 검증

### 8-1. Web Monitoring 확인

Vital Server의 Web Monitoring에서 장비가 표시되는지 확인합니다.

확인할 항목은 다음과 같습니다.

* VR Name이 정상 표시되는지
* 연결 상태가 유지되는지
* 의료기기 신호가 수신되는지
* 파형이 표시되는지
* 장비가 간헐적으로 끊기지 않는지

### 8-2. 파일 업로드 확인

신호 수신 후 파일 업로드가 정상적으로 완료되는지 확인합니다.

PDF에서는 설치 후 서버로 신호가 정상 수신되고 파일 업로드까지 완료된 것을 최종 확인 기준으로 삼았습니다.

파일 전송은 일반적으로 1시간 이내의 랜덤한 시점에 이루어질 수 있습니다. 네트워크가 불안정하거나 음영 구역에 위치한 경우 업로드가 늦어질 수 있습니다.

### 8-3. 실제 의료기기 연결 확인

최종 검증은 Demo Device가 아니라 실제 의료기기 연결 기준으로 진행합니다.

확인할 항목은 다음과 같습니다.

* 의료기기와 Vital Recorder 연결
* Port 설정 일치 여부
* Web Monitoring 신호 수신 여부
* 파형 표시 여부
* 파일 생성 여부
* Vital Server 업로드 여부

## 9. 문제 진단

### 9-1. 관리자 페이지 접속 실패

관리자 페이지가 열리지 않으면 다음 순서로 확인합니다.

1. 장비 전원 연결 여부
2. 첫 부팅 후 3~5분 이상 대기 여부
3. LAN 케이블 연결 상태
4. 노트북 이더넷 IP 수동 설정 여부
5. 접속 주소가 `http://192.168.137.2`인지 확인
6. 노트북 WiFi를 끄고 재시도
7. 5분 추가 대기 후 재시도

### 9-2. Web Monitoring 연결 불안정

Web Monitoring에서 장비가 연결되었다가 끊기는 경우 다음을 확인합니다.

* 병원 WiFi 신호 강도
* 장비 위치가 네트워크 음영 구역인지 여부
* 서버 IP 및 Port 설정
* Vital Server 접근 가능 여부
* 장비 전원 공급 안정성
* 로그 파일

네트워크 문제나 서버 연결 오류가 발생하면 VRZ가 리부트되거나 Vital Recorder가 재시작될 수 있습니다.

### 9-3. 파일이 과도하게 많이 생성되는 경우

짧은 간격으로 파일이 반복 생성되는 경우, Vital Recorder가 정상적으로 녹화를 종료하지 못하고 재시작되는 상황을 의심합니다.

가능한 원인은 다음과 같습니다.

* 네트워크 불안정
* 서버 연결 오류
* 전원 공급 불안정
* 구버전 Vital Recorder 이미지
* 장비 재부팅 또는 서비스 재시작

이 경우 신규 이미지 재설치를 우선 검토합니다.

### 9-4. gzip 압축 오류

gzip 압축 오류는 파일 저장이 정상적으로 종료되지 못했을 때 발생할 수 있습니다.

PDF에서는 네트워크 문제나 서버 연결 오류로 인해 VRZ가 리부트되거나 Vital Recorder가 재시작되면, gzip 파일 끝부분에 필요한 코드가 기록되지 않아 압축 오류가 발생할 수 있다고 설명되어 있습니다.

다만 파일 내부 데이터 자체는 유지될 수 있으며, Vital Recorder 소프트웨어나 Vital Server의 `my-files`에서 미리보기가 가능할 수 있습니다.

### 9-5. 업그레이드 실패

Vital Server의 Web Monitoring 또는 VR Upgrade 기능으로 자동 업그레이드가 되지 않는 경우가 있습니다.

특히 구형 장비에서는 다음 문제가 발생할 수 있습니다.

* 자동 업그레이드 실패
* 업그레이드 후에도 기존 버전 유지
* 부팅 실패
* 64bit 이미지 비호환

이 경우에는 자동 업그레이드보다 SD 카드에 신규 이미지를 직접 설치하는 방식으로 진행합니다.
